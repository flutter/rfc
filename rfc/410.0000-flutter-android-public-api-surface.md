# RFC 410.0000: Flutter Android Embedder Public API Surface and Encapsulation

## Overview

> [!IMPORTANT]
> This RFC defines the supported public Java/Kotlin API surface of the Flutter Android embedder (**50** types across **16** packages) and locks down the remaining **128** internal types, internal constructors, and `@VisibleForTesting` methods as `package-private`.

Why:

- **86% (153 of 178)** of top-level types in [`engine/src/flutter/shell/platform/android/io/flutter/`](https://github.com/flutter/flutter/tree/66b3ad90177ccbd2963836a5556076b370622fe4/engine/src/flutter/shell/platform/android/io/flutter) are `public`, and [`gen_javadoc.py`](https://github.com/flutter/flutter/blob/66b3ad90177ccbd2963836a5556076b370622fe4/engine/src/flutter/tools/javadoc/gen_javadoc.py) publishes **20 of 23** packages—including `FlutterJNI`, `PlatformViewsController`, `AccessibilityBridge`, `TextInputPlugin`, and `systemchannels.*`—to `api.flutter.dev/javadoc/`.
- Internal classes were marked `public` only because Java's `package-private` visibility does not cross subpackages (`io.flutter.embedding.android` vs. `io.flutter.embedding.engine` vs. `io.flutter.plugin.platform`).
- **139** `@VisibleForTesting` members are marked `public` even though unit tests in [`test/io/flutter/`](https://github.com/flutter/flutter/tree/66b3ad90177ccbd2963836a5556076b370622fe4/engine/src/flutter/shell/platform/android/test/io/flutter) already reside in the same Java packages.
- Leaving internal plumbing `public` blocks the [Android Embedder C-API Migration](https://github.com/flutter/rfc/pull/24), which needs to refactor or remove `FlutterJNI`, `PlatformViewsController`, and internal channels without breaking external callers.

### Goals

- Define the supported public API surface for Add-to-App hosts and Android plugins.
- Lock down all **128** internal types and internal members on public classes as `package-private`.
- Migrate the 4 internal API usages in `flutter/packages` to existing public APIs.
- Enforce the boundary in CI (`public_api.txt`) and [`gen_javadoc.py`](https://github.com/flutter/flutter/blob/66b3ad90177ccbd2963836a5556076b370622fe4/engine/src/flutter/tools/javadoc/gen_javadoc.py).

### Non-Goals

- Redesigning the v2 plugin or Activity/Fragment embedding architecture.
- Changing Dart-to-engine platform channel names or binary wire formats.

#### Phase 1: Immediate Non-Breaking Lockdown & CI Guard

1. Fix the 4 internal API usages in `flutter/packages`.
2. Drop `public` in-place from the **28** internal top-level types that already have zero cross-package callers, and from all **139** `@VisibleForTesting` members.
3. Replace the implemented internal interfaces on `FlutterView` with private inner delegates.
4. Update [`gen_javadoc.py`](https://github.com/flutter/flutter/blob/66b3ad90177ccbd2963836a5556076b370622fe4/engine/src/flutter/tools/javadoc/gen_javadoc.py) to pass `-public` and remove the 9 internal-only packages.
5. Add a bytecode signature golden test (`engine/src/flutter/shell/platform/android/api/public_api.txt`) that fails CI if any unapproved `public` or `protected` symbol is added to `flutter.jar`.

#### Phase 2: Deprecate Cross-Package Internals (1 Stable Release)

1. Land the replacement host methods on `FlutterEngine` and `getActivityLifecycle()` on `ActivityPluginBinding`.
2. Annotate the remaining **75** cross-package internal classes and internal members on `FlutterEngine`, `FlutterView`, `FlutterRenderer`, and `DartExecutor` with `@RestrictTo(RestrictTo.Scope.LIBRARY_GROUP)` and `@Deprecated(since = "Flutter X.Y", forRemoval = true)`.
3. Publish a breaking-change migration guide on `docs.flutter.dev`.

## Alternatives Considered

- **`@RestrictTo(RestrictTo.Scope.LIBRARY_GROUP)` without `package-private`:** `@RestrictTo` is only an Android Lint check; bytecode remains `ACC_PUBLIC`. Callers can bypass it with `@SuppressLint("RestrictedApi")` or when Lint is disabled, which still prevents removing or renaming internal classes like `FlutterJNI` during the C-API migration.
- **Java Platform Module System (`module-info.java`):** D8/R8 DEX compilation and the Android Runtime (ART) verifier ignore JPMS module boundaries, and Android Gradle builds put `flutter.jar` on the classpath rather than the module path.
- **Kotlin `internal` visibility:** Kotlin `internal` declarations compile to `public` in JVM/DEX bytecode, remaining accessible to external Java callers unless they are `package-private`.
- **Build-time bytecode repackaging (JarJar / R8):** Rewriting access flags in bytecode without matching source packages causes `IllegalAccessError` across subpackages at runtime and diverges stack traces from source files.
